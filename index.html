表示モード

キーマップ上部の「一覧表示（L0-L4）」「単一レイヤー表示」のタブで切り替えます。

モード表示内容用途
一覧表示（デフォルト）L0〜L4 の 5 レイヤー（BASE / NAV / SYM / ADJ / ADJ_NAV）を 1 セルに同時表示。各セル内の位置: 中央＝L0 BASE / 左上＝L1 NAV / 右上＝L2 SYM / 右下＝L3 ADJ / 左下＝L4 ADJ_NAV日常使用するレイヤー間の関係（同じ物理キーが何になるか）を俯瞰したいとき
単一レイヤー表示レイヤータブで選択した 1 レイヤーを通常表示。L0〜L9 の全 10 レイヤーが対象1 レイヤーの詳細を確認したいとき、スロット番号やバインディング原文を見たいとき、L5〜L9（CTRL_NUM / GUI_NUM / ALT_NUM / BOOT / NAV_FAST）を確認したいとき

一覧表示モード中にレイヤータブをクリックすると、そのレイヤーのラベルが赤強調されます（L0 BASE は中央のデフォルト位置のため強調されません）。修飾キーは記号で短縮表記されます: ^=LCtrl / +=LShift / #=LGui / !=LAlt（例: ^Z = LCtrl+Z）。

レイヤー概要

QMK 側 (olsk60) の L0〜L7 と一対一で揃えた構成（L8 BOOT と L9 NAV_FAST は ZMK 固有）。

L名前用途入り方
0BASE通常入力（ルートレイヤー）初期状態
1NAVナビゲーション・マウスクリック・スクロール・F15〜F18・ScrollBoost・メディア。スクロールキーは &msc SCRL_* をタップ即反応に調整済（下記「ポインティング（グライドポイント）」参照）左親指 /（&lt_hold_tap 1 SLASH）長押し
2SYM記号・テンキー・括弧マクロ。本レイヤー中はグライドポイントがスクロール化される右親指 Space（&lalt_space）長押し
3ADJカーソル移動・編集・F キー右親指 変換 / 英数（&henkan_lt_adj）長押し
4ADJ_NAVCtrl 系拡張ショートカット・Shift+クリックなどNAV と ADJ が同時アクティブになると conditional_layers が自動有効化。Path A／Path B の両方から到達可能（下記「ADJ_NAV 入場経路」参照）
5CTRL_NUMCtrl+0〜9 のショートカット（タブ切替など）] 位置（&lt_hold_tap 5 RIGHT_BRACKET）長押し
6GUI_NUMGui(Win/Cmd)+0〜9 のショートカット\ 位置（&lt_hold_tap 6 BACKSLASH）長押し

9NAV_FASTホイールキー加速（QMK SCROLL_BOOST_KEY のホイール部分のみ近似移植）NAV 中に左手 B（&mo 9）を押下中のみ

カスタム behavior

tapping-term-ms は TAPPING_TERM_MS = 240ms（toucan.keymap 内で定数化）。タップ/ホールド判別はすべて hold-preferred。

表記意味
&mt_hold_tap MOD KEYタップ＝KEY 入力、ホールド＝MOD 単体押下（標準 &mt の引数を TAPPING_TERM_MS で固定化した版）
&lt_hold_tap N KEYタップ＝KEY 入力、ホールド＝レイヤー N をモメンタリで有効化（標準 &lt 相当）。KEY 部は単純なキーコード専用（LC(ENTER) のような修飾付きはタップ側で発火しないことがあるため、専用 hold-tap を別途用意する）
&adj_nav_ctl_ent N 0NAV(1) #40 専用 hold-tap。タップ＝&macro_ctl_enter（= LCtrl+Enter）、ホールド＝レイヤー N（実体は ADJ）をモメンタリ有効化。NAV アクティブ中に長押しすると ADJ も同時アクティブになり、conditional_layers 経由で ADJ_NAV に入場する経路（Path B）として機能する。汎用 &lt_hold_tap に LC(ENTER) を渡す方法は ZMK の hold-tap 解決で誤動作するケースがあったため、タップ側を 0 引数マクロに分離して安定化した版。QMK ADJ_NAV_CTRL_ENT 相当。第 2 引数はマクロ側で未使用のダミー（ZMK hold-tap は #binding-cells = <2> 固定）
&to_nav_sft_ent N 0ADJ(3) #38 専用 hold-tap。タップ＝&macro_sft_enter（= LShift+Enter、QMK ADJ #42 相当）、ホールド＝レイヤー N（実体は NAV）をモメンタリ有効化。ADJ アクティブ中に長押しすると NAV も同時アクティブになり、conditional_layers 経由で ADJ_NAV に入場する経路（Path A）として機能する。短く押せば従来通り LShift+Enter を送る。第 2 引数はダミー
&lalt_spacemod-morph。通常時は &lt_hold_tap 2 SPACE（タップで Space、ホールドで SYM 有効化）、ただしLAlt 押下中にタップすると LAlt+Tab を送る
&henkan_lt_adjmod-morph。通常時は &lt_hold_tap 3 LANGUAGE_1（タップで かな、ホールドで ADJ 有効化）、LShift がアクティブな状態でタップすると LShift+F14 を送る。
QMK 側の HENKAN_LT_ADJ は「無変換 MT 由来の LShift のみ」かつ「pinky LShift 非押下」が条件だったが、ZMK では物理キーを区別できないため LShift アクティブ全般で F14 が発火する

コンボ

  • スロット #36 + #37 + #38 同時押し（親指列の左3つ）→ &mo 8 でレイヤー 8（BOOT）モメンタリ有効化
  • BASE 層に限り、スロット #37 + #40（無変換 + 変換）を 40ms 以内に同時押し → &kp ENTER（QMK 側 COMBO 移植）

conditional_layers と ADJ_NAV 入場経路

  • NAV(1) と ADJ(3) が同時アクティブのとき、自動的にレイヤー 4（ADJ_NAV）が有効化される
  • ADJ_NAV への入場経路は Path A / Path B の 2 経路、いずれも conditional_layers 経由で対称に発火する設計:
  • Path A（変換 → /）: 変換（BASE #40 = &henkan_lt_adj）を長押し → ADJ アクティブ → 続けて /（ADJ #38 = &to_nav_sft_ent NAV 0）を長押し → NAV も合流 → conditional_layers が発火して ADJ_NAV 有効化。
    短く 変換+/ をタップした場合は LShift+Enter が送出される（QMK ADJ #42 と同じ動作）。
  • Path B（/ → 変換）: /（BASE #38）を長押し → NAV アクティブ → 続けて 変換（NAV #40 = &adj_nav_ctl_ent ADJ 0）を長押し → ADJ も合流 → conditional_layers が発火して ADJ_NAV 有効化。
    短く /+変換 をタップした場合は LCtrl+Enter が送出される（QMK NAV #44 と同じ動作）。
  • 設計補足: QMK 側（olsk60）は両 Path とも layer_on(L_ADJ_NAV) を直接呼び出して ADJ_NAV を活性化する直接活性化方式。ZMK 側で同等の &mo ADJ_NAV を使う直接活性化を試みると、conditional_layers が「if-layers 条件（NAV AND ADJ）を満たしていない」と判断して ADJ_NAV を即時 OFF にしてしまうため安定しない。そのため ZMK では両 Path とも conditional_layers 経由の間接活性化に統一している。

ポインティング（グライドポイント）

  • レイヤー 2（SYM）のみ zip_xy_to_scroll_mapper によりスクロール化される（nav 中はカーソル移動のまま）
  • レイヤー 9（NAV_FAST）でホイールキーの移動量が増大（&msc MOVE_X/Y(±90)。ZMK_POINTING_DEFAULT_SCRL_VAL=30 の 3 倍）

スクロール挙動チューニング（NAV のホイールキー）

ZMK の &msc SCRL_* は QMK の KC_MS_WH_* と内部モデルが異なる。QMK は押下時にホイール 1 ティックを即座に HID 送信する離散イベント型だが、ZMK は「仮想速度 × 経過時間」を蓄積して ±1 を超えた瞬間に 1 段の HID スクロールを送る積分型。既定パラメータのままだと「100ms 未満のタップではスクロールが 1 段も発火しない」現象が起きる。

本キーマップでは QMK olsk60 のスクロール体験に近づけるため、以下 2 点をチューニング済（config/toucan.keymap 冒頭参照）。

項目既定本キーマップ意図
ZMK_POINTING_DEFAULT_SCRL_VAL（案A）1030仮想速度を 3 倍に。初回スクロールティック発火までの時間が ~100ms → ~32〜48ms に短縮されてタップ即反応になる
&msc { time-to-max-speed-ms / acceleration-exponent / delay-ms }（案B）300 / 0 / 00 / 0 / 0立ち上がりの加速ランプを排除して、押下瞬間から最大速度に到達させる（将来 acceleration-exponent を 1 以上に変えたときの取りこぼし防止保険）

体感が「速すぎる」場合は ZMK_POINTING_DEFAULT_SCRL_VAL を 20〜25 に下げる。「まだ遅い」なら 40〜50 に上げる。NAV_FAST の MOVE_X/Y(±90) は必ず ZMK_POINTING_DEFAULT_SCRL_VAL より大きく保つ（同値以下だと NAV_FAST のほうが遅くなる逆転現象が起きる）。

QMK 側からの移植で省略した機能

  • 音機能全般（ZELDA_PUZZLE_SOLVED_KEY など）— ZMK では音再生未対応のため
  • MB3_SCROLL_KEY（QMK L0 #54）— ZMK に対応スロットなし。SYM 層中のグライドポイント自動スクロールで部分的に代替
  • SCROLL_BOOST_KEY のトラックポイントスクロール倍率部分 — QMK olsk60 側はトラックポイント搭載だが、ZMK toucan はグライドポイント（タッチパッド）搭載でそもそも該当しない。ホイールキー加速だけ NAV_FAST(L9) として残存
  • QMK L8 L_DANGER（PS/2 マウス速度プロファイル・EEPROM クリア・音声トグル）— L0〜L7 のみ移植対象のため未移植
  • エンコーダマップ — toucan にエンコーダなし

AIへキーマップ修正を指示する方法

次の方法のいずれかで指定することが推奨です。

  • スロット番号 … 画面上の #37 のように出ている番号で「レイヤー 2 のスロット 37 を &kp ENTER に」と書く（toucan.keymap の bindings 配列の並びと一致）。
  • レイヤー + 見た目位置 … 「L1 を表示した状態で、Q の位置」「親指列の一番左」など。
  • いまのラベル … 「WH↑ になっているキーを ○○ に」。

複数キーは箇条書きにすると安全です。新規マクロやカスタム behavior が必要なら、その旨も書いてください。

メンテナンス（HTML と .keymap を同期する手順）

本 HTML の LAYERS[].bindings は、config/toucan.keymap の各レイヤーの bindings = <...> の並び順そのままを文字列化したものです。toucan.keymap を変更したら、次の手順で本 HTML を更新してください。

  • 変更したレイヤーの bindings を取り出し、空白を整えて 42 要素の文字列配列にする
  • 本 HTML の対応する LAYERS[] エントリの bindings を上書きする
  • 新しい behavior / マクロを増やしたときは、ZMK_BEHAVIOR_LABELS（完全一致辞書）または ZMK_PATTERNS（正規表現）を必要に応じて追記する
  • ブラウザでこの HTML を開き、各レイヤータブを切り替えて表示崩れがないか確認する

JIS/US の切替は表示のみで、ファームウェアの挙動には影響しません。

L0〜L9 … &mo/&lt/&lt_hold_tap で参照するレイヤー番号。
M1/M2/M3 … &mkp MB1/MB2/MB3（マウス左/中/右クリック）。WH↑/↓/←/→ … &msc SCRL_*。
